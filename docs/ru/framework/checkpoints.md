# Чекпоинты и откат

Агенты SGR умеют сохранять состояние своего выполнения по ходу работы —
чтобы можно было **откатиться на предыдущий шаг**, **восстановить агента после
перезапуска процесса** и **возобновить сессию** (в том числе через Agent Client
Protocol).

Чекпоинтинг **выключен по умолчанию**: без него агент ведёт себя ровно как
раньше и не делает снапшотов.

## Что хранит чекпоинт

Каждый чекпоинт (`AgentCheckpoint`) содержит всё необходимое для восстановления
агента на конкретном шаге:

- `agent_id`, `def_name`, `step` (номер итерации) и `created_at`;
- исходные `task_messages` и текущий `conversation`;
- восстановимый `context` — состояние, итерация, searches, sources, счётчики,
  `custom_context`, текущее рассуждение и результат выполнения.

Несериализуемые поля намеренно исключены: событие `asyncio` для clarification
(создаётся заново при восстановлении) и разрешённые skills (пере-резолвятся из
конфига).

## Конфигурация

Включается в блоке `execution.checkpoint`:

```yaml
execution:
  checkpoint:
    enabled: true          # снапшот на каждом шаге
    backend: "file"        # "memory" (в процессе) или "file" (переживает рестарт)
    dir: "checkpoints"     # директория для файлового бэкенда
    max_history: 20        # хранить только последние N шагов на агента (null = без лимита)
```

- **`memory`** — снапшоты в памяти процесса (теряются при рестарте).
- **`file`** — по одному JSON-файлу на шаг в `dir/{agent_id}/`, так что агента
  можно восстановить после падения или перезапуска.

Снапшот делается **в начале каждой итерации**, поэтому последний чекпоинт всегда
содержит состояние вплоть до предыдущего шага включительно — падение в середине
шага не теряет уже зафиксированный прогресс.

## Программный API

Каждый `BaseAgent` предоставляет:

```python
agent.checkpoint()          # сохранить снапшот сейчас, вернёт AgentCheckpoint
agent.list_checkpoints()    # -> list[AgentCheckpoint], по возрастанию шага
agent.rollback(step=2)      # восстановить conversation + context из шага 2
agent.rollback()            # восстановить из последнего чекпоинта
```

Откат заменяет живые `conversation` и `context` сохранённым снапшотом
(создаётся свежее событие clarification). Бросает `RuntimeError`, если стор не
настроен, и `ValueError`, если такого шага нет.

### Восстановление нового агента

Пересобрать агента из чекпоинта через фабрику:

```python
from sgr_agent_core import AgentFactory, FileCheckpointStore

store = FileCheckpointStore("checkpoints")
checkpoint = store.latest(agent_id)
agent = await AgentFactory.restore(checkpoint, checkpoint_store=store)
```

`restore` находит определение агента в `GlobalConfig` по `def_name` (или
принимает явный `agent_def=`), сохраняет id из чекпоинта и заново применяет
сохранённые conversation и context.

## REST API

При включённом чекпоинтинге HTTP-сервер предоставляет:

- `GET /agents/{agent_id}/checkpoints` — список сохранённых чекпоинтов;
- `POST /agents/{agent_id}/rollback` — тело `{"step": 2}` (без `step` — до
  последнего); откатывает **живого** агента;
- `POST /agents/{agent_id}/restore` — пересобрать агента из последнего чекпоинта
  (например, после рестарта) и вернуть его в реестр сервера.

Все три возвращают `404`, если чекпоинтинг выключен или чекпоинтов нет.

## Возобновление сессии ACP

Мост Agent Client Protocol сообщает `load_session=true`. Чекпоинты, сделанные во
время prompt, помечаются `session_id` ACP, а `load_session` пересобирает сессию
из последнего чекпоинта — так клиент может переподключиться и продолжить после
перезапуска.
